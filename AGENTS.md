# AGENTS.md

Instructions for coding agents working in this repository. People should start at [README.md](README.md).
Claude Code reads this file through [CLAUDE.md](CLAUDE.md). GitHub Copilot reads it too, and also
[.github/copilot-instructions.md](.github/copilot-instructions.md), which repeats the rules below in brief and
adds a review checklist. Keep the three in step.

## What this repository is

Binary Canticle is a draft protocol for looping, lossy, signed broadcast between AI agent sessions, plus
runnable spikes that test it. It is not a product, has no release, and its wire format is not stable.

Which document wins, highest first:

1. [`rfc/0001-binary-canticle.md`](rfc/0001-binary-canticle.md), RFC-0001, the one place the design is written
   down. Decisions are in §23.1, open questions in §23.2 and work items in §23.3.
2. [`prototype/canticle-station/README.md`](prototype/canticle-station/README.md): what the spike implements,
   section by section, and what it does not. Where the code departs from the RFC, that README says so. A
   departure it does not mention is a bug, or an amendment to propose.
3. Everything in `proto/`, `spike/` and `scratch/` is lineage that RFC-0001 supersedes (its Appendix A maps
   each file). Read it for history; never cite it as current behaviour.

## Set up and test

Use Python 3.11, as CI does, and keep the virtual environment outside the repository:

```sh
python3.11 -m venv ~/.venvs/canticle-dev && . ~/.venvs/canticle-dev/bin/activate
pip install --require-hashes --only-binary=:all: --no-deps -r .github/ci/requirements-station.txt
pip install --no-deps -e prototype/canticle-station
```

From the repository root:

```sh
# Everything CI's station-tests job runs (about a minute).
PYTHONPATH=prototype/canticle-station python -m unittest discover -s prototype/canticle-station/tests

# One module, or tests whose names match a pattern.
PYTHONPATH=prototype/canticle-station python -m unittest discover -s prototype/canticle-station/tests -p 'test_wire.py'
PYTHONPATH=prototype/canticle-station python -m unittest discover -s prototype/canticle-station/tests -k committed_vectors

# CI fails if the tests leave changed or untracked files.
git status --porcelain
```

- `test_station.py`, `test_daemon.py` and `test_join_snapshot.py` take 10 to 30 s each. The other modules take
  a few seconds or less. Run the module you changed first, then the whole suite.
- The tests use loopback UDP, unix sockets and temporary directories. They need no network, no root and no
  keys of yours.
- CI's other job runs the measurement harness's own tests: install `.github/ci/requirements-harness.txt`,
  then `PYTHONPATH=prototype/canticle-station python -m unittest discover -s prototype/protocol-dynamics/tests`.
- Do not run `prototype/protocol-dynamics/run_all.sh` or `prototype/canticle-station/proofs/web-lanes/run.sh`.
  They need root, network namespaces and nftables, and their committed results are attested evidence. A rerun
  is a new measurement, not a test.

## Wire and protocol compatibility

- **The RFC comes first.** A change to the bytes on the wire, to what the receptor emits, or to an identifier
  derivation starts as an RFC-0001 amendment unless the RFC already says it. Code that gets ahead of the RFC
  is a departure, and the prototype README must list it.
- **Frame v2** (RFC §9). Every key, known or not, is covered by the signature. Receivers ignore unknown keys
  unless `crit` lists them, and a change that old receivers must not misread needs a new `version` byte
  (§9.5). The decoder is deliberately stricter than the RFC in two places (floats and tags, map-key types;
  see the prototype README); keep it so unless the RFC changes.
- **Identifiers** (RFC §5). A key id is SHA-256(public key)[0:8]. A `stream_id` is
  SHA-256("canticle-stream/v2" ‖ 0 ‖ name)[0:4]. A collision is refused, never rehashed.
- **Carousel invariants** (RFC §3.4). A station holds no per-listener state and accepts nothing from
  listeners (I-1, I-2). Remaining life never resets (I-3). A repeat changes nothing derived (I-4).
- **Vectors** (RFC §9.13). They stay candidates until a second, independent implementation reproduces them.
  `test_wire.py` checks that the committed file equals the generator's output, so regenerate it with
  `canticle vectors`; never edit it.
- **Receptor record v1** (RFC §14.18.3). Every record carries `v: "canticle-receptor-record/1"`. A binding
  ignores unknown fields, and a new required field or a changed meaning needs a new major version. §14.18 is
  frozen against literal commit SHAs (D29), so changes go through an amendment.
- **The second implementation.** karmaterminal/frond-ear (a private repository) has a TypeScript port. It
  copies `vectors/frame-v2-candidates.json` and two record v1 captures byte for byte, and records each one's
  SHA-256 and source commit in `test/fixtures/canticle/SOURCE.md`. A change to any of them needs a matching
  update there; say so in your pull request.
- The step-by-step procedure is
  [`.agents/skills/canticle-wire-change/SKILL.md`](.agents/skills/canticle-wire-change/SKILL.md).

## Trust, keys and deployment: do not improvise

- Never create keys, manifests, `stations.toml` files or listener state inside the repository, and never
  commit them. Tests use temporary directories. `prototype/canticle-station/.gitignore` ignores `*.key` and
  `fleet.json` under that directory only.
- The spike's fleet manifest is **unsigned**: whoever can write the file chooses the keys a listener trusts.
  Don't present it as fleet trust, and never derive trust from names, addresses, DNS or payloads (I-11).
- Don't turn multicast on, change a host's `stations.toml`, start long-running stations, daemons or
  listeners, install the example systemd units, or bind anything beyond loopback unless the task asks for
  exactly that. `canticle doctor` reports multicast and never decides it (RFC §11.2).
- Never route heard text into an agent session as instructions, and never re-sing heard content. Heard
  content is data (I-6, §14.12). Landing into sessions is work item S3, and receivers are silent-only until
  it exists (D1, D25).
- Agents hold no alarm, quarantine or control keys (D14).
- Don't publish anything to a package or skill registry (PyPI, ClawHub or another). Publication is a
  separate, human-decided gate (#88).

## Conventions

- One branch per change and a pull request to `main`. Pull requests merge with merge commits. Never rewrite
  history on a shared branch.
- Keep the CI boundary of `tests.yml`: a read-only token, no secrets, no `pull_request_target`, actions pinned
  to commit SHAs, and dependencies from the hash-locked files in `.github/ci/`.
- RFC amendments follow the pattern already in the RFC. Mark each change where it lands ("Amendment <id>
  (#<issue>):"). Add a dated revision paragraph under "Status of this memo". Record a new decision in §23.1 as
  proposed until the princes approve its pull request. Keep §23.2, §23.3 and the prototype README in step.
- Cite decisions and evidence by RFC section, issue or pull request number, or commit SHA. Never cite a
  Discord message ID.
- The people are the six princes, the two scribe-princes and figs (the human pet, the RFC's "owner").
  "Gardener" is retired (#35). RFC §2 is the vocabulary for the protocol itself.
