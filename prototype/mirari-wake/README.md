# Mirari's Wake — local emitter experiment (#119)

This is an operator-started, one-actor fixture worker. It reads only explicitly shareable JSONL metadata supplied by its actor, not transcripts, tool results, model reasoning, session databases, or Canticle receiver records. No service installation, automatic activation, network discovery, or receiver wake exists here. The ordinary carrier beacon is unrelated.

The source is a regular, non-symlink file capped at 1 MiB. Each line is JSON with `actor`, `origin: "actor"`, `shareable: true`, `lineage: "local"`, `kind` (event/tool/file/summary), stable `id`, and a short `topic` label. Extra fields are ignored, including raw bodies. A conservative topic grammar and secret/Canticle filters reject suspicious rows before summarization. The output is deterministic and contains only labels, a source digest prefix and a batch identity; it never contains raw log bodies. The fixture is read-only; maintainers must curate topics before adding a line. This is not a general redactor for arbitrary text.

Create an operator-owned authorization JSON outside the repository naming `enabled: true`, exact `actor`, exact absolute `source`, `station`, `audience: "lan"`, `stream: "wake"`, `ttl_s` (1–300), `cadence_s` (30–3600), and `inactive_s` (30–86400). Set `enabled: false` to revoke before the next tick. Keep authorization, state and fixture files outside the repository. Example manual invocation:

```sh
python prototype/mirari-wake/beacon.py --auth /private/auth.json --source /private/fixture.jsonl --state /private/beacon-state.json --actor alice --station-socket /run/user/1000/canticle/familiar-control.sock
```

The socket **must be the existing station control socket** granting `wake:chatter`; the current standalone host daemon socket is receptor-only and discards publish requests. The worker requests LAN scope, a bounded TTL, and a deterministic state key. It never creates a station or key. It writes a local checkpoint only after station acceptance and stops after inactivity. This is **at-least-once attempt**, not exactly-once delivery: if the station accepts the item but the response is lost, or the process fails before the checkpoint's atomic replace, retry emits the same batch a second time with a new station sequence. The `state_key` is a class-stability/audit field, **not** a dedupe or idempotency key in the station API. If the checkpoint is durable, an ordinary restart skips accepted rows. If the source changes before retry, the source digest and batch identity also change. A station acceptance does not prove receiver observation; signed UDP can be lost. No attempt is made to retract an already accepted item on revocation. Frozen fixtures are preferred.

Run `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=prototype/canticle-station python -m unittest discover -s prototype/mirari-wake -p 'test_*.py'`. The unit tests use fake source and sink, including an accepted-publish/failed-checkpoint retry proof. The integration test uses a temporary station key and manifest, Unix control socket, signed loopback UDP and a separate listener. It checks station acceptance, one receiver item, omitted raw body, and receiver-local expiry. No live station, fleet address, or deployed receiver is contacted.

Receiver mute is **not a station-layer feature**: it belongs to the OpenClaw binding after receptor admission. The local interop test in `prototype/openclaw-canticle/test/interop.test.ts` runs this emitter's `tick` against a real temporary station control socket, signed loopback UDP, real daemon, and the TypeScript binding. With `mirari:wake` muted before publication, it checks the admitted item is journaled with `disposition: muted`, remains manually readable (as untrusted text), and remains muted after unmute. It also checks actor authorization revocation refuses a subsequent publish, and a binding with no tuned streams does not journal a later accepted publish. The plugin implements explicit reads only, so “never pushed” is a binding disposition/policy claim, not a live push-path observation. No deployed receiver is exercised.

Before any fleet pilot: verify these mute/uninterested and opt-out behaviors on the deployed receiver binding; review source authorization/audience; provision the `wake` stream and control socket in the manifest; and accept the documented at-least-once crash semantics or add station-side idempotency with a separate protocol change. No live broadcast is part of this prototype.
